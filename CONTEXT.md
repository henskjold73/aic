# AIC Calendar — Context

Domain glossary and gotchas for people (and agents) working in this repo. See `README.md` for setup and architecture.

## Terms
- **AIU** — GitHub Copilot AI Credit unit. Source column `total_nano_aiu` ÷ 1e9.
- **Budget** — user's monthly AIU allowance, entered in the browser, stored per account and month in `account_budgets` (mirrored to `usage.budget`).
- **Sync key / sync UUID** — generated by the install script on a machine, saved to `~/.config/aic/uuid`; it is what that machine's script writes to. A write-only secret, one per machine; never returned by an API.
- **Team** — a set of accounts under a team UUID (the team id is the read credential), with per-team display names. An account may be in several teams.
- **Burn rate / ratio** — `actualPerDay / allowedPerDay`; 1 = on pace. Colours in `src/lib/constants.ts` (`offsetColor`, `todayColor`).
- **Run-out day** — projected day the budget is exhausted; snapped past weekends in `CalendarGrid`.
- **Project** — optional label from `~/.config/aic/project`, stored on `usage_daily` rows.

## Accounts
- **Account** — a GitHub login (`accounts.github_id`) or a hidden **shadow** account created automatically for each pre-existing sync key.
- **Sync key** — the old UUID; a row in `sync_keys` pointing at an account. Usage is still written per key; account views sum across the account's non-disabled keys.
- Browser identity is the `aic_session` cookie. `src/lib/session.ts` exposes the subject (`"me"` when signed in, else the legacy localStorage UUID); a signed-in browser auto-attaches a leftover localStorage UUID and clears it.
- **Pairing:** the installer asks `ping` for a code (`request_pair_code`), the user enters it on `/devices` while signed in. Codes are hashed, single-use, 15 min; failed guesses are counted per account.
- **Duplicate keys:** two active keys on one account with the same `db_fingerprint` (certain) or ≥2 identical non-zero closed days (likely, vetoed if fingerprints differ) raise a warning showing on the calendar and `/devices`. Users can disable a key (hidden from totals, reversible) or dismiss the pair; a dismissal stops applying if either fingerprint changes. Nothing is auto-disabled.
- `sync_keys.id` is the public handle for a key; `sync_keys.key` is the secret the script writes to.
- **Teams are keyed by account** (`team_members.account_id`, unique per team). `user_uuid` is still filled with a key the member joined with, only so older code can read the table; nothing reads it. Team payloads identify members by account id and never contain a sync key; a member's chart comes from `GET /api/team/{id}/days?member=<account id>` (404 unless that account is in the team).
- **Legacy key-only API:** reads/edits by key alone (`GET /api/usage/{key}*`, `PATCH /api/usage/{key}`, key-based team list/join/leave) work until `LEGACY_KEY_API=off` is set in Vercel, after which they return 403. Script writes (`POST` usage/days/ping) are never affected. Keys that leaked through team payloads before this change are still known to whoever fetched them; ask affected users to re-run the installer after rotating (a new key must be written by the machine itself).

## Gotchas
- `ensureSchema()` (schema + migrations + backfills) runs from the script write routes, team join and every `/api/me/*` call; plain GET routes assume it has already run. Deploying needs no manual migration.
- Postgres NUMERIC/BIGINT come back as strings; always go through `num`/`int`/`iso`/`dateKey` in `api/db.ts`.
- The sync script hard-codes the API host; script version lives in three places (both scripts + `vite.config.ts`). Installed scripts never self-update; users re-run the installer.
- Sessions are stateless signed cookies (`SESSION_SECRET`); there is no per-session revoke. OAuth env: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, optional `APP_URL`.
- `usage_daily.project` is overwritten only when the new value is non-null (`COALESCE`).
- Month keys use UTC (`toISOString().slice(0,7)`) on the server; `today` uses DB `CURRENT_DATE`.
- Budget updates (`PATCH /api/me/budget`, or the legacy `PATCH /api/usage/{key}`) only handle the current month.
- Legacy: `aic_team_id` localStorage key is migrated into `aic_team_ids`; `/api/admin/migrate` is retired.
- `public/usage.json` is an empty `{}` leftover from the Blob era.
- `.vercel`, `.env*` are gitignored; `DATABASE_URL`/`POSTGRES_URL` is required at import time of `api/db.ts`.
